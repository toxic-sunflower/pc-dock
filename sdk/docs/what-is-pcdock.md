# Что такое PC Dock и зачем он нужен

Если вы видите проект впервые, начните с этой страницы. Здесь нет команд, которые надо запускать: только объяснение, что это, как устроено и что с этим можно делать.

## Одним абзацем

**PC Dock управляет Android-телефонами с компьютера.** Вы подключаете телефон кабелем, запускаете на компьютере программу, и после этого можно:
смотреть, что на экране телефона; нажимать, листать и печатать на нём; открывать и закрывать приложения; копировать файлы; и главное, **писать
сценарии**, которые делают всё это сами, без человека, на одном телефоне или на десяти сразу.

Это не приложение с кнопками, а набор программ-«демонов», которые работают в фоне, и протокол, по которому с ними разговаривают другие программы.
Интерфейс вы можете сделать любой (или не делать вовсе: всё работает из скрипта).

## Какие задачи это решает

| Задача | Как это выглядит |
|---|---|
| **Автотесты мобильного приложения** | Сценарий открывает приложение, нажимает кнопки, проверяет, что на экране появился нужный текст. Если проверка не прошла, сохраняется скриншот. |
| **Ферма телефонов** | Десяток телефонов на одном USB-хабе. Один сценарий запускается на всех, расписанием, например каждую ночь. |
| **Рутина на телефоне** | «Открыть приложение, зайти в раздел, нажать кнопку, подождать, скопировать результат». Записали один раз, дальше работает само. |
| **Удалённое управление** | Экран телефона и ввод в браузере или в своей программе. Телефон стоит на столе, вы работаете за компьютером. |
| **Подготовка телефонов** | Поставить приложение, выдать права, очистить данные, сменить IP через мобильные данные: из скрипта, на всех телефонах. |

## Из чего это состоит

```
   Ваша программа или скрипт              Компьютер                              Телефон
 ┌──────────────────────────┐      ┌──────────────────────────┐        ┌───────────────────────┐
 │ веб-страница, Python,    │ ───► │ pcdockd                  │ ─ USB ─►│ приложение PC Dock    │
 │ ваш сервис, pcdock-autod │ ◄─── │ (ферма: держит телефоны) │        │ или ADB               │
 └──────────────────────────┘      └──────────────────────────┘        └───────────────────────┘
       разговор по протоколу             работает в фоне
       (JSON по TCP или WebSocket)
```

Три программы, все запускаются из командной строки:

- **`pcdockd`** (демон фермы) главная. Находит телефоны на USB, подключается к ним, держит связь, отдаёт картинку с экрана и принимает команды:
  «нажми сюда», «открой приложение», «дай список приложений». Сам ничего не делает по своей воле.
- **`pcdock-autod`** (демон автоматизации) запускает **сценарии** на языке Lua. Сценарий это обычный текстовый файл с шагами: открыть, нажать, проверить.
  Демон выполняет его, пишет журнал, сохраняет отчёт. Он общается с телефонами через `pcdockd`.
- **`pcdock-check`** проверяет, что на вашем компьютере всё готово: видит ли он телефон, есть ли доступ к USB. Если что-то не так, пишет, что делать.

Остальное (демо-страница в браузере, pygame-окно) это примеры клиентов, чтобы увидеть работу глазами.

## Как телефон подключается: два пути

Телефон и компьютер соединены кабелем, но говорить по нему можно двумя способами. Вам не обязательно выбирать вручную: `pcdockd` сам находит рабочий путь.

| | **ADB** | **USB-аксессуар (AOA)** |
|---|---|---|
| Что нужно на телефоне | включить «Отладку по USB» и один раз нажать «Разрешить» | установить приложение PC Dock, подтвердить его запуск и разрешить запись экрана |
| Ввод | команды `adb`, как будто человек нажимает пальцем | настоящее USB-устройство: телефон считает, что к нему подключили мышь и тачскрин |
| Плюсы | проще начать, приложение на телефон ставить не нужно | ввод как от настоящих USB-устройств; работает без «Отладки по USB» |
| Минусы | нужна включённая «Отладка по USB» | сложнее начать, больше диалогов на телефоне |
| Команды над приложениями (запуск, список, поиск по экрану) | работают все | работает часть, через приложение PC Dock (ограничения Android) |

**С чего начать:** ADB. Он проще, и все команды из этой документации с ним работают.

## Что можно делать

Каждый пункт это команда протокола; подробности и примеры в [рецептах](recipes.md).

- **Смотреть**: картинка экрана (JPEG-кадры), звук приложений.
- **Нажимать**: касание, свайп, несколько пальцев, мышь, клавиши, ввод текста, кнопки «Назад» и «Домой».
- **Искать на экране**: найти кнопку по тексту или подписи и нажать на неё, не зная координат (`tap_on("Войти")`).
- **Приложения**: открыть, закрыть, список, версия, установить APK, удалить, стереть данные.
- **Телефон**: модель, батарея, память, процессор; Wi-Fi, мобильные данные, режим полёта; «не гасить экран»; внешний IP.
- **Файлы**: положить на телефон, забрать с телефона.
- **Сценарии**: Lua-скрипты с проверками, журналом и отчётом; параметры; цепочки; расписание.
- **Запись сценария**: вы сами нажимаете на телефоне, а PC Dock превращает это в готовый сценарий.
- **Диагностика**: что с телефоном и какие были ошибки (`Health`), журнал телефона (`logcat`), причины закрытия приложения.

## Чего PC Dock не делает

- **Не «видит» картинку.** Сценарий не распознаёт изображения и текст на скриншоте. Он ищет элементы по дереву интерфейса (как это делает `uiautomator`).
  Если приложение рисует всё само (игра), найти кнопку по тексту нельзя, только нажать по координатам.
- **Не работает с iPhone.** Только Android.
- **Не шифрует связь.** Демон слушает только свой компьютер. Если выводите наружу, делайте это через SSH-туннель или VPN.
- **Не обходит защиту.** Если телефон не разрешил отладку или не подтверждён компьютер, PC Dock ничего не сделает, а скажет, что нажать на телефоне.

## Словарь

| Слово | Что это |
|---|---|
| **Ферма** | то, что в `pcdockd` держит все телефоны: находит, подключает, переключает пути |
| **Демон** | программа, которая работает в фоне и ждёт команд |
| **Протокол** | договорённость, как программам разговаривать: какие бывают команды и что они отвечают. У PC Dock это JSON по TCP или WebSocket |
| **Клиент** | любая программа, которая шлёт демону команды: ваш скрипт, веб-страница, `pcdock-autod` |
| **Номер телефона** | число (1, 2, 3…), которое ферма выдаёт телефону; используется во всех командах |
| **Путь, транспорт** | способ связи с телефоном: `adb`, `usb` (AOA), `serial` |
| **AOA** | Android Open Accessory: режим, в котором телефон считает компьютер «аксессуаром» и общается с его приложением напрямую |
| **ADB** | Android Debug Bridge: стандартный инструмент Google для управления телефоном через отладку |
| **Компаньон** | приложение PC Dock на телефоне. Нужно для пути AOA |
| **Сценарий** | текстовый файл на Lua: что сделать на телефоне и что проверить |
| **Прогон** | один запуск сценария. У него есть номер, журнал событий и итоговый отчёт |
| **Цепочка** | несколько сценариев подряд, по кругу, с повторами |
| **Элемент экрана** | кнопка, текст, поле: то, что находит `UiFind`. У него есть текст, подпись, `id` и координаты |
| **Доли экрана** | координаты от 0 до 1: `0.5, 0.5` это центр экрана, на любом телефоне |
