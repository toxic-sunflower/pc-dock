# Быстрый старт

Цель: за 10–15 минут пройти путь от чистой машины до первого сценария, который сам открывает приложение на вашем телефоне и проверяет результат.
Если вы не знаете, что такое «ферма», «демон» и «путь подключения», прочитайте сначала [«Что такое PC Dock»](what-is-pcdock.md): это пять минут.

**Что понадобится:** компьютер (Linux, macOS или Windows), Android-телефон, USB-кабель, который передаёт данные (не только зарядка).

В каждом шаге три части: **что делаем и зачем**, **что должны увидеть**, **если не так**.

## Шаг 0. Установите программы

Что делаем: ставим `pcdockd`, `pcdock-autod` и `pcdock-check`. Зачем: это сами программы. Способы установки (скрипт, `cargo install`, из исходников) описаны в
[install.md](install.md). Самый короткий на Linux и macOS:

```bash
curl -fsSL https://pc-dock.prozorov.me/install.sh | sh
```

Должны увидеть: в конце установщик пишет, куда поставил программы (`~/.pcdock/bin`). Проверка: `pcdockd --help` печатает список параметров.

Если не так: команда не найдена, значит `~/.pcdock/bin` нет в `PATH`. Добавьте строку, которую подсказал установщик, в `~/.profile` и откройте новый терминал.

Вам ещё нужен **APK сервера** для режима ADB (маленькая программа, которую `pcdockd` сам положит на телефон). Он лежит рядом с релизом
(`pcdock-server-<версия>.apk`); при сборке из исходников он получается командой `./gradlew :server-adb:assembleDebug` в `devices/android/app-screencast`.

## Шаг 1. Подготовьте телефон

Что делаем: разрешаем компьютеру управлять телефоном. Зачем: Android по умолчанию такого не позволяет, это сделано для вашей безопасности.

1. Откройте «Настройки → О телефоне» и несколько раз нажмите на «Номер сборки» (на разных телефонах называется по-разному), пока не появится сообщение, что вы стали разработчиком.
2. Откройте «Настройки → Для разработчиков» и включите **«Отладка по USB»**.
3. Подключите телефон кабелем к компьютеру.
4. На телефоне появится вопрос «Разрешить отладку по USB для этого компьютера?». Отметьте «Всегда разрешать» и нажмите «Разрешить».

Если не так: вопрос не появился. Попробуйте другой кабель (самая частая причина) или выберите на телефоне режим USB «Передача файлов». На Xiaomi, Oppo и других оболочках
есть дополнительные переключатели («Установка через USB», «Отладка по USB (настройки безопасности)»), подробности в [operations.md](operations.md#4-подготовка-телефона).

## Шаг 2. Проверьте компьютер

Что делаем: запускаем самопроверку. Зачем: если что-то не работает, лучше узнать здесь, а не посреди сценария.

```bash
pcdock-check --server-apk pcdock-server-v0.1.0-alpha.3.apk
```

Должны увидеть (у вас будут свой серийный номер и размер экрана):

```
[ПРОШЛО ] система: linux x86_64
[ПРОШЛО ] USB: libusb работает, телефонов на шине: 1
[ПРОШЛО ] ADB: сервер ADB отвечает, устройств: 1
[ПРОШЛО ] телефоны: найдено: 1
[ПРОШЛО ] телефон 1 (usb, 35022250): готовность: ready через 6.8 с
[ПРОШЛО ] телефон 1 (usb, 35022250): экран: 1080x2412, поток 1080x2412, поворот 0
[ПРОШЛО ] телефон 1 (usb, 35022250): видео: кадров 5, в среднем 80 КБ
[ПРОПУСК] телефон 1 (usb, 35022250): ввод: выключено (добавьте --input: свайп вниз и вверх на экране телефона)

Итого: всё хорошо. Прошло 7, внимание 0, провалов 0, пропущено 1.
```

Если не так: у каждой строки с провалом написано, что делать. Частые случаи:

| Сообщение | Что значит | Что делать |
|---|---|---|
| нет прав на USB | Linux не даёт обычному пользователю открыть устройство | правила udev: [transports.md](transports.md#linux) |
| `needs_auth` | телефон ждёт, когда вы нажмёте «Разрешить» | нажать «Разрешить» на телефоне |
| телефонов на шине: 0 | компьютер не видит телефон | другой кабель, другой порт; в WSL2 нужен проброс USB: [transports.md](transports.md#wsl2) |

Проверка ввода (`pcdock-check --input`) сделает на телефоне свайп вниз, вверх и нажмёт «Назад». Запускайте её, когда экран телефона можно трогать.

## Шаг 3. Запустите ферму

Что делаем: запускаем `pcdockd`. Зачем: это главная программа. Она держит связь с телефонами, и все остальные (сценарии, веб-страница) разговаривают с ней.

```bash
pcdockd --auto --server-apk pcdock-server-v0.1.0-alpha.3.apk
```

`--auto` значит «принимай все найденные телефоны». Без него надо перечислять телефоны вручную.

Должны увидеть:

```
INFO  pcdockd] TCP: 127.0.0.1:9001
INFO  pcdockd] local: pcdock
INFO  pcdockd] pcdockd работает, трубки: [1]
```

Последняя строка значит: есть один телефон, у него номер 1. Окно не закрывайте: демон работает, пока оно открыто. (Как запустить его службой, чтобы он стартовал сам:
[operations.md](operations.md).)

Если не так: «трубки: []» значит, что телефон не найден. Проверьте шаг 2.

Демон слушает только ваш компьютер (`127.0.0.1`), поэтому пароль не нужен. Как выставить его в сеть безопасно: [daemon.md](daemon.md#слушатели).

## Шаг 4. Поговорите с фермой

Что делаем: отправляем демону первую команду. Зачем: понять, как это устроено, прежде чем писать сценарии. Демон понимает команды в виде JSON. Для примеров
есть маленький клиент на Python: [`sdk/examples/pcdock.py`](../examples/pcdock.py) (нужен только Python 3, ничего ставить не надо).

В новом терминале:

```bash
python3 sdk/examples/pcdock.py '{"op":"List"}'
```

`List` значит «покажи телефоны». Ответ:

```json
{
  "ev": "Phones",
  "phones": [1],
  "details": [
    {
      "phone": 1,
      "state": "ready",
      "transport": "adb",
      "serial": "35022250",
      "name": "pcdock-server/1.0",
      "display": {"screen_w": 1080, "screen_h": 2412, "dpi": 480, "rotation": 0}
    }
  ]
}
```

Что здесь важно: `state: "ready"` телефон готов; `transport: "adb"` связь идёт по ADB; `phone: 1` номер, который теперь нужен во всех командах.

Теперь спросим про сам телефон и откроем на нём «Настройки»:

```bash
python3 sdk/examples/pcdock.py '{"op":"DeviceInfo","phone":1}' '{"op":"LaunchApp","phone":1,"package":"com.android.settings"}'
```

Первая команда вернёт модель, версию Android и размер экрана (`"model": "CPH2505"`, `"android": "15"`, …). Вторая откроет «Настройки»: посмотрите на телефон.
Ответ `{"ev": "DeviceResult", "op": "LaunchApp", "data": {}}` значит «сделано».

Если не так: `Error` с текстом. Он всегда говорит, в чём дело («нет трубки 5», «у телефона неизвестен серийник»). Все команды: [protocol.md](protocol.md).

## Шаг 5. Первый сценарий

Что делаем: пишем сценарий и запускаем его через `pcdock-autod`. Зачем: сценарий выполняется сам и оставляет отчёт, это основной способ использования.

Запустите демон автоматизации (в новом терминале; `pcdockd` должен работать):

```bash
pcdock-autod --farm 127.0.0.1:9001 --data ./autod-data
```

Сохраните сценарий в файл `settings.lua`:

```lua
test("Открыть Настройки и найти Wi-Fi", function()
  local p = phones()[1]                              -- первый телефон, выделенный прогону
  assert.truthy(p:wait_ready(10), "телефон готов")   -- подождать до 10 с; если нет, тест провален
  step("открываем Настройки")                        -- запись в журнале прогона
  p:launch("com.android.settings")                   -- открыть приложение
  step("ждём пункт Wi-Fi")
  assert.truthy(p:wait_for("Wi-Fi", 8), "пункт Wi-Fi на экране")   -- ждать до 8 с, пока на экране появится текст «Wi-Fi»
  log.info("версия Android", p:device_info().android)
end)
```

Что в нём: `test(...)` один тест, у него есть имя; `phones()[1]` ваш телефон; `assert.truthy(...)` проверка, и если она не прошла, тест остановится с провалом;
`p:wait_for("Wi-Fi", 8)` ищет на экране элемент с этим текстом. Все функции: [autod.md](autod.md).

Отправьте сценарий демону и запустите (из корня репозитория; если у вас только установленные программы, положите `pcdock.py` рядом и поправьте `sys.path`):

```python
# run.py
import sys, time
sys.path.insert(0, "sdk/examples")
from pcdock import Conn

c = Conn("127.0.0.1:9101")                       # порт pcdock-autod
saved = c.ask({"op": "ScriptPut", "name": "Настройки: Wi-Fi", "source": open("settings.lua").read()})
run = c.ask({"op": "Run", "script": saved["script"], "follow": False})
time.sleep(10)
print(c.ask({"op": "RunInfo", "run": run["run"]})["report"]["status"])
```

```bash
python3 run.py
```

Должны увидеть слово `passed`, а на телефоне открытые «Настройки». Подробный итог лежит в `./autod-data/runs/<номер>/report.json`:

```json
{
  "status": "passed",
  "report": {
    "duration_ms": 4130, "passed": 1, "failed": 0, "errors": 0,
    "tests": [{"name": "Открыть Настройки и найти Wi-Fi", "status": "passed", "asserts_passed": 2, "asserts_failed": 0}]
  }
}
```

Рядом лежит `events.jsonl`: журнал всего, что происходило (каждый шаг, каждая проверка, каждое сообщение `log.info`).

Если не так:

| Что видите | Что значит |
|---|---|
| статус `failed` | проверка не прошла; в `events.jsonl` строка `"kind":"assert"` с `"ok":false` и сообщением; рядом сохранён кадр экрана |
| статус `error` | ошибка в самом сценарии (опечатка, вызов несуществующего метода); текст ошибки в `report.json` |
| `телефон N занят прогоном …` | на телефоне уже идёт другой прогон; два прогона на одном телефоне невозможны |
| `нет телефона 1` | `pcdock-autod` не видит `pcdockd`; проверьте адрес `--farm` |
