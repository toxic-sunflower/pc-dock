# Рецепты

Готовые примеры типичных задач. Каждый рецепт: **задача**, **как сделать**, **что получится**. Все они рассчитаны на то, что вы прошли
[быстрый старт](getting-started.md): `pcdockd` работает, телефон в состоянии `ready`.

Сценарии (кусочки на Lua) вставляются в файл сценария и запускаются через `pcdock-autod`, как в быстром старте. Отдельные команды протокола
отправляются клиентом [`sdk/examples/pcdock.py`](../examples/pcdock.py) на порт `9001` (`pcdockd`) или `9101` (`pcdock-autod`).

Правила, которые пригодятся во всех рецептах:

- **Координаты** это доли экрана от 0 до 1: `0.5, 0.5` центр, `0.5, 0.9` низ посередине, на любом телефоне.
- **Цель поиска** на экране: `"Войти"` текст целиком, `"~Вой"` текст содержит, `"id:login"` идентификатор, `"desc:Назад"` подпись. Варианты через `|`: `"Войти|Log in"`.
- **`p`** это телефон: `local p = phones()[1]` первый телефон прогона.

## 1. Нажать кнопку по тексту

**Задача:** открыть приложение «Часы» и нажать вкладку «Будильник», не зная координат.

```lua
test("Вкладка будильника", function()
  local p = phones()[1]
  p:launch("com.coloros.alarmclock")                 -- пакет приложения
  local tab = p:tap_on("Alarm", {timeout = 5})       -- ждать до 5 с, найти и нажать
  assert.truthy(tab, "вкладка нашлась")
end)
```

**Что получится:** `tap_on` ищет элемент по тексту, нажимает в его центр и возвращает сам элемент (или `nil`, если не нашёл за время `timeout`).
Пакет приложения (`com.coloros.alarmclock`) узнаётся командой `ListApps` (см. рецепт 12) или `p:apps()`. Текст вкладки зависит от языка телефона: на русском это «Будильник».

## 2. Ввести текст в поле

**Задача:** найти поле «Поиск», нажать в него и набрать запрос.

```lua
test("Поиск", function()
  local p = phones()[1]
  p:launch("com.android.settings")
  type_into(p, "Search settings", "wifi")   -- текст поля зависит от языка телефона; нажать в поле и набрать
end)
```

**Что получится:** `type_into` нажимает в поле, потом печатает. **Ограничение:** по ADB набирается только латиница, цифры и знаки; для кириллицы и эмодзи нужен путь AOA с приложением на телефоне.

## 3. Листать, пока не найдётся

**Задача:** в длинном списке найти пункт «О телефоне».

```lua
test("Дойти до пункта", function()
  local p = phones()[1]
  p:launch("com.android.settings")
  local el = scroll_until(p, "About phone", {max = 10})   -- листать список не больше 10 раз
  assert.truthy(el, "пункт найден")
  p:tap(el.x, el.y)
end)
```

## 4. Подождать, пока что-то появится или исчезнет

**Задача:** после нажатия «Войти» дождаться главного экрана; если появилось окно с ошибкой, упасть с понятным сообщением.

```lua
local p = phones()[1]
p:tap_on("Войти")
local found = find_any(p, {"Главная", "Ошибка"}, 10)     -- первая найденная из целей, ждём до 10 с
assert.truthy(found, "после входа ничего не появилось")
assert.ne(found.text, "Ошибка", "вход завершился ошибкой")
p:wait_gone("Загрузка", 15)                               -- ждать, пока исчезнет индикатор
```

**Повтор при сбоях:** `retry(3, 2, function() return p:tap_on("Обновить") end)` пробует до 3 раз с паузой 2 секунды, пока функция не вернёт истину.

## 5. Проверить, что приложение установлено нужной версии

```lua
test("Версия приложения", function()
  local p = phones()[1]
  local app = p:app_info("com.android.chrome")
  assert.truthy(app.installed, "Chrome установлен")
  log.info("версия", app.version_name)
  assert.truthy(app.version_code > 0, "есть номер версии")
end)
```

`app_info` возвращает `installed`, `version_name`, `version_code`, `enabled`, даты установки и обновления и подписи сертификата (`signatures`).
Установка: `p:install_apk("/data/local/tmp/app.apk", {sha256 = "…"})` ставит APK, который уже лежит на телефоне (его кладёт команда `FilePut`; нужен `pcdockd --files`).
Ошибка установки приходит с причиной (`INSTALL_FAILED_VERSION_DOWNGRADE` и т. п.).

## 6. Записать сценарий, просто нажимая на телефоне

**Задача:** не писать Lua руками, а один раз проделать действия пальцем.

Запись идёт в `pcdockd` (порт 9001), телефон должен быть по ADB. Скрипт запускает запись, вы нажимаете на телефоне, скрипт останавливает запись:

```python
from pcdock import Conn
c = Conn()                                    # pcdockd, 127.0.0.1:9001
c.ask({"op": "RecordStart", "phone": 1})      # дальше нажимайте на телефоне
input("Нажмите Enter, когда закончите действия на телефоне… ")
result = c.ask({"op": "RecordStop", "phone": 1, "name": "Проверка Wi-Fi", "origin": "записано вручную"})
print(result["lua"])
```

**Что получится** (настоящий результат: открыли «Настройки», нажали «Wi-Fi», нажали переключатель):

```lua
-- записано вручную
test("Проверка Wi-Fi", function()
  local p = phones()[1]
  sleep(5)
  p:swipe(0.7647, 0.3215, 0.7017, 0.4887, {duration = 0.44})
  sleep(5)
  p:tap_on("id:navigationBarBackground")
  sleep(2.9)
  p:tap_on("Wi-Fi")
  sleep(2.9)
  p:tap_on("On")
end)
```

Нажатия превратились в `tap_on("текст")`, если под пальцем был элемент с подписью, иначе в `tap(x, y)` по координатам. Паузы между шагами сохранились.
Это готовый сценарий: его можно сохранить командой `ScriptPut` и запускать.

**Править запись, пока она идёт.** Посмотреть шаги: `RecordState`. Удалить или изменить шаг: `RecordSetSteps` (список шагов целиком; чего в списке нет, то удалено).
Добавить проверку «на экране видно X»: `RecordScreen` покажет элементы экрана, `RecordAddCheck` с номером элемента добавит шаг
`assert.truthy(p:find_one("…"))`. Отменить запись: `RecordDiscard`. Все поля: [protocol.md](protocol.md#запись-сценария).

## 7. Запускать сценарий по расписанию

**Задача:** каждый будний день в 03:00 по местному времени запускать сценарий.

```python
from pcdock import Conn
c = Conn("127.0.0.1:9101")                    # pcdock-autod
c.ask({"op": "SchedulePut", "name": "Ночная проверка",
       "rule": {"daily": "03:00", "days": [1, 2, 3, 4, 5], "utc_offset_min": 180},   # 1 = понедельник; +3 часа к UTC
       "target": {"script": "s1a21dac357e"}})                                          # номер сценария из ScriptPut
```

Другие правила: `{"every": 600}` каждые 10 минут; `{"at": время_в_мс}` один раз. Расписание хранится на диске и переживает перезапуск демона.
Запуски, пропущенные за время простоя, не наверстываются; пока предыдущий запуск не закончился, новый пропускается.

## 8. Несколько сценариев подряд, с повторами

**Задача:** три сценария по очереди; если второй упал, повторить его до двух раз; весь круг сделать пять раз.

```python
c.ask({"op": "RunChain", "name": "Обход", "rounds": 5, "round_pause": 60,
       "steps": [
           {"script": "s1"},
           {"script": "s2", "on_fail": "retry", "retries": 2, "pause": 10},
           {"script": "s3", "on_fail": "continue"},
       ]})
```

`on_fail`: `stop` остановить цепочку (по умолчанию), `continue` идти дальше, `retry` повторить. Итог цепочки: `chains/<номер>/chain.json`.

## 9. Сменить IP-адрес и проверить интернет

**Задача:** выключить и включить мобильные данные, дождаться сети, узнать новый внешний адрес.

```lua
test("Сменить IP", function()
  local p = phones()[1]
  local before = wait_online(p, 10)
  log.info("был адрес", before.local_ip)
  local result = net_restart(p, {method = "mobile_data", attempts = 3, require_new_ip = true})
  assert.truthy(result, "сеть вернулась с новым адресом")
  log.info("стал", result.new_ip, "попыток", result.attempts)
  log.info("внешний адрес", p:public_ip())
end)
```

`method = "airplane"` использует режим полёта вместо мобильных данных. Свой адрес проверки внешнего IP: `p:public_ip("https://example.com/ip")` или параметр запуска `check_url`.

## 10. Работать с несколькими телефонами

```lua
test("Все телефоны отвечают", function()
  for _, p in ipairs(phones()) do
    local info = p:device_info()
    log.info("телефон", p.id, info.model, "Android", info.android)
    assert.truthy(p:installed("com.android.chrome"), "Chrome есть на телефоне " .. p.id)
  end
end)
```

`phones()` это телефоны, выделенные прогону. По умолчанию все готовые; выбрать конкретные можно при запуске: `{"op": "Run", "script": "…", "phones": [1, 3]}` по номерам
или `"phones": ["35022250"]` по серийным номерам (серийный номер не меняется при переподключении, номер фермы может).

Каждый телефон занят одним прогоном: второй прогон на том же телефоне получит отказ «телефон N занят прогоном …».

## 11. Сохранять журнал и запись экрана прогона

**Задача:** чтобы по упавшему прогону можно было разобраться, сохранять журнал телефона и видео.

```python
c.ask({"op": "Run", "script": "s1a21dac357e",
       "device_logs": True,                   # logcat каждого телефона после прогона
       "exit_info": ["com.example.app"],      # почему закрывалось это приложение
       "record": 5})                          # запись экрана, 5 кадров в секунду
```

В папке прогона (`./autod-data/runs/<номер>/`) появятся: `phone-1-logcat.txt`, `phone-1-exit-com.example.app.txt`, `rec-1.mp4` (если на компьютере есть `ffmpeg`;
иначе кадры JPEG в `rec-1/`). Если что-то не сохранилось, об этом будет предупреждение в журнале прогона.

## 12. Узнать, какие приложения есть на телефоне

```bash
python3 sdk/examples/pcdock.py '{"op":"ListApps","phone":1}'
```

Ответ: `{"data": {"packages": ["com.android.chrome", "com.android.settings", …]}}`. Без `"all": true` только приложения со значком запуска. Какое приложение сейчас на экране:
`{"op":"ForegroundApp","phone":1}` вернёт `{"package": "com.android.settings", "activity": ".Settings"}`.

## 13. Работать без ADB (только USB-аксессуар)

Если у телефона нет доступного ADB, часть команд выполняет приложение-компаньон на телефоне: запуск приложений, список и сведения о приложениях, состояние экрана и сети, буфер обмена.
Это ограничения Android, а не программы: например, `Button back` без ADB недоступна, а чтение буфера обмена работает, только когда приложение в фокусе.

Чтобы вызвать компаньона напрямую (даже если у телефона есть и ADB):

```bash
python3 sdk/examples/pcdock.py '{"op":"CompanionCall","phone":1,"call":{"op":"LaunchApp","package":"com.android.settings"}}'
```

Права компаньона (доступ к статистике использования, уведомления) выдаются одной командой, пока ADB ещё доступен: `{"op":"CompanionPermissions","phone":1}`.
Список всех команд компаньона: [`PROTOCOL.md`](../../devices/android/PROTOCOL.md), раздел 9.

## 14. Дать кому-то только смотреть

**Задача:** показать экран телефона коллеге, чтобы он не мог ничего нажать.

```bash
pcdockd --auto --token главный-пароль --role-token view=пароль-для-просмотра --tcp 0.0.0.0:9001
```

Клиент с токеном `пароль-для-просмотра` может смотреть экран и читать сведения, но не может нажимать, открывать приложения и работать с файлами. Роли: `view` просмотр, `input`
просмотр и ввод, `nofiles` всё, кроме файлов. **Внимание:** связь не шифруется, наружу выставляйте только через SSH-туннель или VPN.

## 15. Узнать, что происходит с фермой

```bash
python3 sdk/examples/pcdock.py '{"op":"Health"}'
```

Ответ: версия сервера, версия протокола, список телефонов (у неготового есть поле `error` с причиной и подсказкой) и `errors` последние 100 ошибок демона:
обрывы связи, сбои команд, битые пакеты. Это первое, что стоит смотреть, когда «что-то не работает».
