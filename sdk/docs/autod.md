# Демон автоматизации `pcdock-autod`

Отдельный процесс, который запускает сценарии на Lua как автотесты. Он клиент `pcdockd`: подписывается на кадры, шлёт ввод и ничем не мешает ферме
(ни памятью, ни потоками; медленный клиент отключается сервером, а видео телефона идёт по спросу). Телефоны он сам не трогает.

```
 UI / CI ──(протокол автоматизации)──► pcdock-autod ──(протокол демона)──► pcdockd ──► телефоны
```

Расширение под компьютерное зрение предусмотрено (кадры уже приходят в процесс автоматизации), но в первую версию CV не входит.

## Запуск

```bash
pcdockd --auto --server-apk server-adb-debug.apk              # ферма
pcdock-autod --farm 127.0.0.1:9001 --data ./autod-data         # автоматизация
```

| Параметр | Назначение |
|---|---|
| `--farm <адрес>` | где `pcdockd`: `host:port`, `tcp://host:port`, `local:имя` (по умолчанию `127.0.0.1:9001`) |
| `--farm-token` | пароль `pcdockd` (или `PCDOCK_FARM_TOKEN`) |
| `--frame-fps` | сколько кадров в секунду просить у телефона, когда сценарию нужны кадры (по умолчанию 5) |
| `--data <папка>` | папка данных: сценарии и прогоны (по умолчанию `pcdock-autod-data`) |
| `--token` | пароль для клиентов (или `PCDOCK_TOKEN`); без него слушать можно только на localhost |
| `--tcp`, `--ws`, `--local` (+ `--no-…`) | слушатели (по умолчанию `127.0.0.1:9101`, `127.0.0.1:9102`, `pcdock-autod`) |
| `-v` | подробные логи |

Если `pcdockd` недоступен, демон ждёт и переподключается сам (раз в 2 с); пока связи нет, телефонов в списке нет, а запуск сценария на телефон отказывает.
Протокол: [protocol.md](protocol.md#3-pcdock-autod-автоматизация).

## Сценарий

Файл на Lua 5.4 в песочнице: доступны `table`, `string`, `math`, `utf8`, `coroutine` и функции ниже. Нет `io`, `os`, `package`, `debug`, `load*`, `require`.
Выполнение прерывается по команде `Stop` и по сроку прогона (проверка каждые 1000 инструкций и во всех ожиданиях), так что даже `while true do end` останавливается.

Сценарий состоит из тестов:

```lua
before_each(function() log.debug("перед каждым тестом") end)
after_each(function() log.debug("после каждого, даже если тест упал") end)

test("шторка открывается", function()
  local p = phones()[1]
  assert.truthy(p:wait_ready(10), "телефон готов")        -- провал останавливает тест
  step("свайп вниз")                                      -- шаг в логе прогона
  p:swipe(0.5, 0.01, 0.5, 0.5, {duration = 0.3})
  expect.truthy(p:wait_change(3), "экран изменился")      -- провал фиксируется, тест идёт дальше
  p:key("esc")
end)
```

Если в сценарии нет `test`, сам сценарий считается одним тестом (под именем сценария).

### Проверки и логи

| Функция | Действие |
|---|---|
| `assert(v, msg)`, `assert.truthy(v, msg)`, `assert.falsy(v, msg)` | провал останавливает тест |
| `assert.eq(a, b, msg)`, `assert.ne(a, b, msg)` | равенство (числа, строки, таблицы глубоко) |
| `assert.near(a, b, eps, msg)` | числа с допуском |
| `assert.contains(text, sub, msg)`, `assert.matches(text, pattern, msg)` | подстрока / шаблон Lua |
| `expect.*` | те же проверки, но провал только отмечается: тест продолжается |
| `fail(msg)` | сразу провал теста |
| `step(text)` | шаг прогона |
| `log.debug/info/warn/error(...)` | запись в журнал прогона |

При провале автоматически сохраняются последние кадры телефонов прогона (не больше трёх раз за прогон) и появляются вложениями отчёта.

### Время

`sleep(sec)`, `now()` (секунды от начала прогона), `wait_until(fn, timeout, interval)` вызывает `fn`, пока она не вернёт истину (возвращает true или false по сроку).

### Телефоны

Методы приложения (`launch`, `apps`, `foreground`, `ui`, `find`, `wait_for`, `tap_on`, `exit_info`, `ip`) работают с приложением pc-dock,
которое умеет возможности 6–13 (`devices/android/PROTOCOL.md`); телефон без них отвечает `"unsupported"` (`ui`/`find` — ошибкой).

`phones()` список телефонов, выделенных прогону; `phone(id)` один из них. Телефон выделяется эксклюзивно (два прогона на одном телефоне невозможны).
Координаты везде доли экрана `0..1` отображаемой картинки.

| Метод | Действие |
|---|---|
| `p.id`, `p:state()`, `p:info()` | номер, состояние (`ready`…), сведения (серийник, путь, размер экрана, поворот) |
| `p:wait_ready(timeout)` | ждёт `ready` (по умолчанию 30 с), возвращает true/false |
| `p:tap(x, y, opts)` | касание; `opts`: `hold` (с), `pressure`, `size`, `finger` |
| `p:swipe(x1, y1, x2, y2, opts)` | протяжка; `opts`: `duration`, `steps`, `pressure`, `size` |
| `p:touch(phase, x, y, opts)` | одна фаза: `"down"`, `"move"`, `"up"`, `"cancel"` (для жестов из нескольких пальцев: `finger`) |
| `p:key(name_or_usage, opts)` | клавиша по имени (`"a"`, `"enter"`, `"esc"`, `"f1"`) или коду USB HID; `opts.hold` |
| `p:type(text)` | ввод текста: латиница, цифры, пробел и `-=.,/` — набором HID-клавиатуры (заглавные через Shift); всё остальное (кириллица, эмодзи, `#@!`, переводы строк) — через приложение pc-dock (возможность 13 `TEXT_INPUT`, как `p:paste`). Старое приложение без неё — ошибка `app_outdated: …` (обновить pc-dock), сбой ввода — `text_input_failed: …` |
| `p:paste(text)` | вставить любой текст (≤ 16 КБ) в поле с курсором через приложение pc-dock (возможность 13), без набора по клавише: телефон вставляет его службой специальных возможностей («Вставить» или «Задать текст») или кладёт в буфер обмена — тогда автоматизация жмёт Ctrl+V. Возвращает способ: `"paste"`, `"set_text"`, `"clipboard"`; ошибки — как у `p:type` |
| `p:scroll(ticks)`, `p:scroll_h(ticks)` | колесо |
| `p:wake()`, `p:enable(kind, on)` | побудка; включить/выключить устройство (`"touch"`, `"mouse"`, `"keyboard"`) |
| `p:frame(opts)` | кадр экрана; `opts`: `timeout` (5 с), `fresh` (дождаться нового) |
| `p:wait_change(timeout)` | ждёт, пока картинка изменится; возвращает кадр или `nil` |
| `p:push(dest, data, opts)`, `p:pull(src, max)`, `p:ls(path)`, `p:rm(path)` | файлы на телефоне (нужен `pcdockd --files`); `opts.media` |
| `p:launch(pkg, opts)` | открыть приложение; возвращает итог телефона: `"ok"`, `"not_installed"`, `"blocked_bal"`, `"error …"` |
| `p:apps()` | приложения с главным экраном (таблица из ответа телефона) |
| `p:foreground()` | пакет на переднем плане или `nil` |
| `p:ui()` | элементы экрана: XML uiautomator |
| `p:find(sel, opts)` | элемент или `nil`; `sel` — строка (текст целиком) или `{text, text_contains, id, desc, class, index}`; `opts.timeout` — ждать (по умолчанию не ждёт). Элемент: `text, id, desc, class, package, clickable, enabled, x, y` (центр в долях), `bounds` |
| `p:wait_for(sel, timeout)` | ждёт появления элемента (по умолчанию 10 с), true/false |
| `p:tap_on(sel, opts)` | нажать на центр элемента, ждёт его до `opts.timeout` (10 с); нет элемента — ошибка |
| `p:exit_info(pkg, since_ms)` | причины завершения приложения (Android 11+): таблица или строка (`"unsupported"`, `"no_permission"`) |
| `p:ip(url)` | HTTPS GET по сети телефона (внешний IP): таблица или строка-ошибка |
| `p:http{method, url, headers, body, timeout}` | HTTP-запрос к устройству локальной Wi-Fi-сети телефона (админка роутера) через Wi-Fi телефона: `method` — `"GET"` (по умолчанию) или `"POST"`, `url` — `http(s)://` с IPv4 частной сети (`192.168.…`, `10.…`, `172.16–31.…`, `169.254.…`), `headers` — таблица, `body` — только у `POST` (≤ 64 КБ), `timeout` — секунды (10, не больше 30). Возвращает `{ok = true, code, body, headers, ms}` (любой код HTTP, в том числе 401; имена заголовков строчными, несколько `set-cookie` — через `\n`) или `{ok = false, error}`: `bad_url`, `bad_request`, `no_wifi`, `timeout`, `io: …`, `unsupported` (приложение pc-dock без возможности 12 — обновить) |

Кадр (`frame`): `seq`, `pts` (с), `bytes`, `width`, `height`, `phone`, метод `save(name)` кладёт его во вложения прогона.
Первая просьба кадра подписывает автоматизацию на видео телефона (с частотой `--frame-fps`), в конце прогона подписка снимается: если больше никто не смотрит,
телефон перестаёт снимать.

`args` таблица параметров запуска (`Run {args}`).

## Прогон и отчёт

Каждый запуск создаёт папку `runs/<run>/`: `events.jsonl` (все события), `report.json` (итог) и вложения. Отчёт:

```json
{
  "run": "r19a2…", "script": {"id": "s19a2…", "name": "Главный экран"}, "phones": [1],
  "started": 1794431744249, "finished": 1794431744303, "status": "failed",
  "report": {
    "status": "failed", "duration_ms": 53, "passed": 1, "failed": 1, "errors": 0,
    "tests": [{"name": "шторка открывается", "status": "passed", "duration_ms": 31,
               "asserts_passed": 2, "asserts_failed": 0, "error": null}]
  }
}
```

Статус теста: `passed`, `failed` (проверка не прошла), `error` (ошибка в сценарии), `stopped`. Подписчик, подключившийся позже, получает историю с нужного номера и дальше живой поток.

## Ограничения первой версии

- Анализа изображений нет: кадры можно получать, сохранять и сравнивать по факту изменения (`wait_change`), но пикселей, шаблонов и текста сценарий не видит.
- Один сценарий выполняется в одном Lua-состоянии (потоки внутри сценария создавать нельзя); параллельные прогоны на разных телефонах возможны.
- Состояние прогонов хранится на диске, но идущие прогоны при перезапуске демона не продолжаются (останавливаются).
- Ролей доступа нет: общий токен (ролевой доступ относится к приложению над демонами).
